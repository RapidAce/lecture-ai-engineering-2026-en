PEFT: train only part of a model, not the whole model.
FT that updates every parameter is expensive. Methods that train only a small number of parameters, or PEFT, have become mainstream.
Sources: original papers by Houlsby et al. (2019), Li and Liang (2021), Lester et al. (2021), and Hu et al. (2022). Available through the Hugging Face PEFT library.
What is trained, Dettmers et al., Fig. 1:
Full Fine-Tuning: update all parameters; large memory and storage requirements.
LoRA: freeze the base model and update only a small added component.
QLoRA: also compress the base model to 4 bits to save memory.
Main PEFT methods:
Adapters: insert small layers between existing layers and train only those. Houlsby et al., 2019.
Prefix/prompt tuning: prepend trainable virtual tokens to the input. Li and Liang, 2021; Lester et al., 2021.
LoRA: represent and learn weight changes as the product of two small, thin matrices, a low-rank representation. Hu et al., 2022. Currently the most widely used approach.
QLoRA: LoRA plus compression of original weights to 4 bits for even lower memory use. Dettmers et al., 2023; next slide.

Evidence and debate: RAG often works better for adding knowledge.
This does not mean FT can add no knowledge at all. Treat it as a general rule while understanding the exceptions.
Sources: Ovadia et al., EMNLP 2024; Gekhman et al., EMNLP 2024; Biderman et al., TMLR 2024; Zhou et al., LIMA, NeurIPS 2023.
Research findings underlying the general rule:
Ovadia et al. (2024): on knowledge tasks, RAG consistently outperformed FT directly on documents.
Gekhman et al. (2024): examples containing new knowledge are learned slowly; learning more of them tends to increase errors, or hallucinations.
Biderman et al. (2024): LoRA learns less and forgets less than full FT. It suits small adjustments.
Exceptions and differing findings:
• Continued pre-training, or CPT, on large amounts of text can add language and domain knowledge, as in Japanese Swallow models.
• Training on varied paraphrases of the same fact can make knowledge easier to learn through FT.
• About 1,000 high-quality examples can substantially change behavior, as in LIMA.
• Transferring a large model's behavior to a small one, or distillation, is also used to reduce cost and latency.

Based on **Lecture 3 (Part 6: Memory)**, here is how compaction and cross-session memory differ, along with how daily notes are handled:

### 1. Difference Between Compaction and Cross-Session Memory
* **Compaction (History summarization within the loop):** 
  * Operates **inside the context (same session)**. 
  * It replaces older parts of the conversation history with a summary to help fit the interaction within the model's context limits (Lecture 3, p. 39, 65).
* **Cross-Session Memory (External storage):** 
  * Operates **across sessions**. 
  * It uses external storage (such as files managed via a memory tool or auto-memory) where records are written out and then reloaded into the next session's context so that the agent does not start completely from scratch (Lecture 3, p. 13, 39).

### 2. Do All Daily Notes Become Long-Term Memory?
* **No, not everything is kept.** 
* For example, in systems like OpenClaw, daily notes (`memory/<date>.md`) capture the details of specific sessions, but an automatic nightly review process (a "dreaming" phase) collects candidates, drops duplicates, finds recurring themes, and **moves only what passes the threshold** into long-term memory (`MEMORY.md`) (Lecture 3, p. 40). 
* One-off lookups remain only in the daily notes, preventing long-term memory from bloating with unnecessary information (Lecture 3, p. 40).

Based on Lecture 3 of the AI Engineering Pilot Course (AIE2026), here is how compaction and cross-session memory differ, along with how daily notes are handled:

* **Compaction vs. Cross-Session Memory:** 
  * **Compaction** operates *within the current session* (inside the context). It compresses or summarizes past conversation history to fit within context limits [Lecture 3, p. 39, 65].
